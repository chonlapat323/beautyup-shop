### 2. หมวดหมู่หลัก: แบรนด์ → หมวดหมู่หลัก → คอลเลกชัน → สินค้า

- เดิมการ์ดหมวดหมู่หลักในหน้าแบรนด์ (ดูแลผม, ทำสี, ฟอกสี, ยืดดัด) กดปุ่ม "ดูสินค้า" แล้วไม่ไปไหน เพราะลิงก์ชี้ไปจุดที่ไม่มีในหน้า และหมวดหมู่หลักไม่ได้ผูกกับคอลเลกชันหรือสินค้า
- เพิ่ม "หมวดหมู่หลัก" ในระบบ แต่ละคอลเลกชันเลือกได้ว่าอยู่หมวดหลักไหน
- หน้าแบรนด์แสดงการ์ดหมวดหมู่หลัก กดแล้วเปิดหน้าหมวด แสดงคอลเลกชันในหมวดและสินค้าทั้งหมดของหมวด
- หน้าคอลเลกชันมีปุ่มกลับไปหมวดหลัก และแสดงคอลเลกชันอื่นในหมวดเดียวกัน
- Admin: เมนูใหม่ "หมวดหมู่หลัก" (ใต้ แบรนด์และสินค้า) และหน้าแก้ไขคอลเลกชันมีช่อง "หมวดหมู่หลัก" (แสดงเฉพาะหมวดของแบรนด์ที่เลือก)
- ตอน deploy ระบบย้ายการ์ด 4 ใบในเมนู Fanola มาเป็นหมวดหมู่หลักให้อัตโนมัติ (รูป ชื่อ คำอธิบายเดิม) แล้วเอาบล็อกการ์ดเดิมออกจากเมนู ส่วนการ์ด "ตระกูลผลิตภัณฑ์" ไม่ได้ย้าย เพราะการ์ดคอลเลกชันทั้งหมดอยู่ด้านล่างอยู่แล้ว
- ใส่ข้อมูลตัวอย่าง: จับคู่คอลเลกชันของ Fanola กับหมวดหลัก (เช่น No Yellow Care → ฟอกสีผม, Nutri Care → ดูแลผม) ทีมต้องตรวจและแก้ให้ถูกใน Admin → คอลเลกชัน
- ลบค่าตั้งค่าเก่าของบริการที่เลิกใช้ที่ยังค้างในฐานข้อมูล
- ทดสอบในเครื่องแล้ว: migration ทุกตัวที่ยังไม่ได้ขึ้น server รันผ่าน, หน้าแบรนด์, หน้าหมวด, หน้าคอลเลกชัน และหน้าภาษาอังกฤษแสดงถูกต้อง

### 5. เพิ่มระบบ SEO & AI Search สำหรับสินค้า (Products) ตามต้นแบบระบบมีเดีย

- **ฐานข้อมูล & Admin:**
  - เพิ่มช่อง **"คำค้นหา (แท็ก SEO / AI)"** (`tags`) ในหน้าสร้าง/แก้ไขสินค้า (คั่นด้วยลูกน้ำ เช่น `แชมพูม่วง, ผมฟอก, ลดประกายเหลือง, fanola`)

  - เมื่ออัปโหลดรูปสินค้าใหม่และกดบันทึก ระบบจะเปลี่ยนชื่อไฟล์ใน `/uploads/` อัตโนมัติเป็น `ชื่อแบรนด์-ชื่อสินค้า-คอลเลกชัน-แท็ก-วันที่-1.นามสกุลไฟล์` เพื่อให้ Google Images และ AI เข้าใจรูปภาพได้ทันที
- **หน้าเว็บ & AI Search:**
  - อัปเกรด Metadata (`keywords`, OpenGraph URL/รูปภาพเต็ม) และ `Schema.org/Product` JSON-LD (เพิ่ม `url`, `inLanguage`, `image`, `brand`, `category`, `keywords`, `seller`) ในหน้ารายละเอียดสินค้า
  - แสดงป้าย `#แท็ก` และปุ่มแชร์/QR Code ในหน้ารายละเอียดสินค้า
  - ระบบค้นหาภายในเว็บ (`/search`) สามารถค้นหาสินค้าจากชื่อคอลเลกชันและแท็ก SEO ได้
  - เพิ่มฟีดข้อมูล `/products.json` (2 ภาษา TH/EN) สำหรับให้ AI (ChatGPT, Claude, Perplexity, Gemini) ดึงข้อมูลสินค้าไปตอบคำถามได้โดยตรง เหมือน `/media.json`

### 9. เพิ่มระบบ Breadcrumb บอกตำแหน่งเต็มลำดับขั้น และตัวกรองข้อมูล (Filter Pills) ใน Admin
**ปัญหา:** เมื่อตัดเมนูย่อยออกจากแถบซ้ายแล้ว ผู้ดูแลต้องการรู้ว่าตัวเองกำลังอยู่ตำแหน่งไหนของเมนูใด และเมื่อเข้าไปหน้ารายการข้อมูลที่มีเยอะ (เช่น สินค้า คอลเลกชัน หมวดหลัก ซาลอน ทีมงาน มีเดีย เมนูย่อย) ต้องการตัวกรองแยกดูตามหมวด/แบรนด์ได้ทันที

**แก้ไข:**
- อัปเกรด `apps/admin/src/components/section-flow-bar.tsx` ให้แสดง **Breadcrumb เต็มลำดับขั้น** (`ภาพรวม › เมนูและหน้าเว็บ › เมนู: ... › ส่วนที่กำลังจัดการ › แบรนด์/หมวดที่กรอง หรือ รายการที่กำลังแก้ไข`) พร้อมปุ่มสลับส่วนที่ `1 → 2 → 3 → 4` ของเมนูนั้น
- เพิ่มแถบ **Filter Pills** ในหน้ารายการข้อมูล (`apps/admin/src/app/(dash)/r/[resource]/page.tsx`):
  - กรองตามเมนูหลัก (`menu-items`), ประเภทแบรนด์ (`brands`), แบรนด์ (`main-categories`, `categories`, `products`, `media`), ภูมิภาค (`salons`), ฝ่าย (`team`), ประเภทบทความ (`posts`), หมวดฟอรั่ม (`forum-topics`)
  - กรองย่อยขั้นที่ 2 (Sub-filter): กรองตามหมวดหมู่หลักในหน้าคอลเลกชัน (`categories`), กรองตามคอลเลกชันในหน้าสินค้า (`products`), กรองตามหมวดมีเดียในหน้าคลังมีเดีย (`media`)
  - กรองตามสถานะ: `ทั้งหมด` / `แสดงผลอยู่` / `ซ่อนอยู่` พร้อมตัวเลขจำนวนรายการในแต่ละตัวกรองและปุ่มล้างตัวกรอง
- อัปเดตลัดจัดการหน้าแบรนด์ใน `MenuItemVisualEditor` (`/products/<brand>`) ให้ส่งพารามิเตอร์ `?filter=<brandSlug>` อัตโนมัติ เมื่อกดเข้าหมวดหมู่หลัก คอลเลกชัน หรือสินค้า จะกรองเฉพาะแบรนด์นั้นให้ทันที

**ผลลัพธ์:**
- ผู้ดูแลเห็นตำแหน่งปัจจุบันแบบละเอียดทุกหน้า (ตั้งแต่หน้ารายการจนถึงหน้าแก้ไขรายการย่อย) และกรองหาข้อมูลตามแบรนด์/หมวด/สถานะได้ในคลิกเดียว

### 10. เชื่อมต่อระบบอัปโหลดรูปภาพและไฟล์เข้ากับ DigitalOcean Spaces (S3 CDN) และแก้การแสดงรูปข้ามโดเมนใน Admin
**ปัญหา:**
- รูปที่อยู่ในฝั่งเว็บหลัก (`new.beautyup-enterprise.com`) ไม่แสดงในหน้า Preview ของ Admin (`admin.beautyup-enterprise.com`) เนื่องจากอยู่คนละโดเมน
- ต้องการให้การอัปโหลดรูปและไฟล์ใหม่ทั้งหมดเก็บขึ้น Cloud Object Storage (**DigitalOcean Spaces `sgp1` — `beautyup-media`**) โดยยังคงเก็บไฟล์เดิมในระบบไว้

**แก้ไข:**
- เพิ่ม `apps/admin/next.config.ts` `rewrites()` และ `resolveImg` ใน `MenuItemVisualEditor` เพื่อดึงรูปจากฝั่ง Web และ API มาแสดงในหน้า Admin ได้ทุกจุด
- สร้าง `apps/api/src/common/storage.ts` รองรับการอัปโหลดและเปลี่ยนชื่อไฟล์ SEO บน **DigitalOcean Spaces (S3-Compatible API)** ผ่าน AWS Signature V4 โดยไม่ต้องลงแพ็กเกจเพิ่ม พร้อมสำรองไฟล์ลง `uploads/` ในเครื่องควบคู่กัน
- อัปเดต `AdminUploadsController`, `ForumController`, และ `renameUploads` (`media-files.ts`) ให้ส่งไฟล์ขึ้น DigitalOcean Spaces อัตโนมัติเมื่อตั้งค่า `S3_ACCESS_KEY` และ `S3_SECRET_KEY` ใน `.env`

**ผลลัพธ์:**
- รูปเดิมทั้งหมดยังคงแสดงผลได้ตามปกติทั้งบนหน้าเว็บและหน้า Admin
- รูปและไฟล์ที่อัปโหลดใหม่จะถูกเก็บขึ้น `https://beautyup-media.sgp1.cdn.digitaloceanspaces.com/uploads/...` พร้อมรองรับการเปลี่ยนชื่อไฟล์ SEO อัตโนมัติเมื่อบันทึกสินค้าหรือมีเดีย

**Commit:** `e8054dd`, `a94ce9b`

### 11. บังคับโครงสร้าง `แบรนด์ → หมวดหมู่หลัก → สินค้า` (ส่วน `คอลเลกชัน` ไม่บังคับ)
**ปัญหา:** สินค้าบางหมวดหรือบางแบรนด์ไม่มีคอลเลกชันย่อย (มีเฉพาะแบรนด์และหมวดหมู่หลัก) แต่เดิมสินค้าผูกกับคอลเลกชันอย่างเดียว ทำให้ถ้าไม่เลือกคอลเลกชัน สินค้าจะไม่มีหมวดหมู่หลัก

**แก้ไข:**
- เพิ่ม `mainCategoryId` ในโมเดล `Product` (`apps/api/prisma/schema.prisma` และ migration `20261026162000_product_main_category`) พร้อม backfill หมวดหมู่หลักให้สินค้าเดิมทั้งหมดอัตโนมัติ
- บังคับการกรอกใน `packages/types/src/index.ts` และ `apps/admin/src/lib/fields.ts`:
  - **สินค้า (`products`)**: บังคับเลือก **แบรนด์** (`required`) และ **หมวดหมู่หลัก** (`required` กรองตามแบรนด์) ส่วน **คอลเลกชัน** เป็นตัวเลือกเสริม (`nullable: true` กรองตามหมวดหมู่หลักที่เลือก)
  - **คอลเลกชัน (`categories`)**: บังคับเลือก **แบรนด์** และ **หมวดหมู่หลัก** เสมอ
- อัปเดตหน้าแบรนด์บนเว็บ (`apps/web/src/app/[lang]/products/[brand]/page.tsx`) ให้แสดงสินค้าตามหมวดหมู่หลักได้โดยตรงแม้หมวดนั้นจะไม่มีคอลเลกชันย่อย

## ต้องทำต่อ

- Deploy ขึ้น server (สำรองฐานข้อมูลก่อน) ด้วยคำสั่ง:
  `git pull origin main && pnpm install && pnpm --filter @beautyup/api exec prisma migrate deploy && pnpm build && pm2 reload beautyup-shop-api beautyup-shop-web beautyup-shop-admin`
- หลัง deploy เทส:
  - หน้า Fanola → กดการ์ดหมวดหมู่หลัก → กดคอลเลกชัน → กดการ์ดสินค้า (ต้องเปิดเข้าหน้ารายละเอียดสินค้า `/product/[slug]` โดยตรง ไม่มี popup)
  - หน้ารายละเอียดสินค้า: ตรวจป้าย `#แท็ก` และปุ่มแชร์/QR Code
  - เปิด `/products.json` ตรวจว่าแสดงรายการสินค้าครบ
  - Admin → สินค้า: ลองใส่คำค้นหา (แท็ก SEO / AI) และอัปโหลดรูปใหม่ ตรวจว่าชื่อไฟล์เปลี่ยนอัตโนมัติและมีกล่อง QR Code ด้านล่าง
  - Admin → คอลเลกชัน & หมวดหมู่หลัก: ตรวจว่าแต่ละคอลเลกชันผูกกับหมวดหลักถูกต้อง

## ข้อควรระวัง

- มีทั้งอัปเดตแพ็กเกจ (`next@16.4.3`) และ migration ใหม่ (`20261026120000_product_seo_tags`) ต้องรันทั้ง `pnpm install`, `prisma migrate deploy` และ `pnpm build` ก่อน reload PM2
- ห้ามรัน `pnpm db:seed` บน server
